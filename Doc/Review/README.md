# 人类与AI评审入口

直接用浏览器打开[index.html](index.html)。页面不依赖联网服务、CDN或额外软件包；项目可整体复制，链接按项目相对路径保存。

当前已知问题与优先级见[2026-10-29设计审查](设计审查_2026-10-29.md)。类图中的“范围验收通过”指历史证据，不等于没有缺陷；草稿冲突和全局引用校验等新发现仍待修复。

## 建议阅读

1. **模块总览**：先看多条输入如何汇入共享Core，再看七个代码职责分区。生成契约是可选支路。
2. **核心类图**：按模块查看40个关键类型，点击类查看真实成员、源码位置、直接关系和证据；需要时展开一跳关联。
3. **来源**：分别查看“设计沿革”和“当前实现”。可筛选原设计承接、本轮协作补齐和来源待确认。
4. **状态与边界**：区分范围验收、生产接入、设备验证和发布状态。原章节与道具外围归属待本人确认，不把它当功能缺失。
5. **验证证据**：查看2026-10-28的277项测试与双平台构建，以及生成评审资料时对精确源码的摘要核对。

图只精选关键类型；完整机器声明索引包含整个包。选中类后的关系清单保留全部直接关系，图中按结构关系与当前焦点限制连线，避免线网淹没类名。筛选外的关联数量会单独提示。

类名较长时使用缩放和模块分图；支持键盘选择、打印与当前SVG导出。独立静态图见[class-diagram.svg](class-diagram.svg)，可编辑Mermaid源见[class-diagram.mmd](class-diagram.mmd)。详细沿革见[设计来源与状态说明](设计来源与状态说明.md)。

## 面试时怎样说明

用原设计主线解释为什么把类型、表头、作者资产、双端接口和交换链这样组织；用本次补齐说明旧耦合如何拆开、哪些未完业务被完成、如何验证。图上的来源标签是有证据的设计沿革，不能代替本人解释，更不表示每类作者已逐行审定。

## 给AI的入口

先读项目根的[AI_CONTEXT.md](../../AI_CONTEXT.md)，再用`Tools/Review/query.py`读取有界JSON。机器入口为[engineering-index.json](engineering-index.json)，完整声明导航为[source-inventory.json](source-inventory.json)。先执行`verify`核对是否过期，再引用历史验收结果。

## 维护

修改`architecture-curation.json`维护真实类型、成员与关系，修改`provenance.json`补充本人确认后的来源。运行根目录AI_CONTEXT列出的两条生成命令。页面会把生成日期、历史验收日期和源码匹配状态分别显示，本轮生成资料不重跑Unity测试。
