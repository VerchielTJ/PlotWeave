# 阶段04：Excel与Luban交换

日期：2026-10-28。状态：本批双向交换及文件交接实现、验证、归档完成；外部Luban编译接入仍待验证。

## 原功能对应

源为 `I:/model/Assets/PlotEditor/PlotEditorTools/PlotExcelTools.cs`。新实现位于包的 `Editor/Excel`，共享OpenXML读写基础设施沿用独立原型中的自有代码，不引入NPOI或游戏程序集。

- 枚举：恢复 `__plotenums__.xlsx`，类型全名B列，值名G列、别名H列，类型首行与成员续行。
- Bean：恢复 `__plotbeans__.xlsx`，类型名B列、注释F列，成员名H列、类型I列、注释K列。前两行为嵌套定义的 `##var`。
- 节点：恢复 `剧情基础节点.xlsx`，`##var / ##type / ##`三行，数据从第四行开始。使用配置的物理列索引，Bean成员横向展开并合并表头，列表按节点续行纵向展开。`IsList`决定列表，列名中的星号不用于推断列表。
- 两类文本：分开的对话/常量工作簿，B列KEY，C至G为原5种语言，严格保持语言次序。
- 通用表：保留动态表头、物理列索引、Sheet名和字符串ID。原资产模型将行ID独立存放；若首列未显式定义ID，导出在B列补独立ID列并右移业务列，导回同类资产时还原位置。显式ID列须位于B列，不允许行ID与该单元格冲突。
- Luban交接：恢复原 `OutputPlotDataToLubanData` 的复制职责，只交接配套6份工作簿，备份目标已有文件并核对SHA256，其他文件保留。原函数本身没有执行外部编译器，本批也不把复制文件称为Luban编译成功。

## 入口与操作

`Tools / PlotWeave / 制作工具 / Excel与Luban交换`。

1. 选择工作区，导出到自动生成的新目录。原工作簿不覆盖。
2. 用Excel编辑这6份配套工作簿。
3. 选择目录并“检查导入”，只解析与校验工作副本。
4. 查看更新、新增、保留的节点数量，再应用计划。资产和表格在检查后若发生变化，计划作废。
5. 需要交接时选择Luban数据目录，复制完成记录会明确注明外部编译器未运行。

样例入口：`Tools / PlotWeave / 迁移样例 / 验证原布局表格往返`。每次在 `Assets/PlotWeaveMigration/Stage04_Exchange/Runs/<id>` 新建独立接收工作区，运行资产→工作簿→新工作区资产，并交接到独立LubanData目录。

## 数据一致性

导入节点采用合并策略：更新表内节点、新增表内新节点、保留未出现在表中的节点。类型、表头、文本和演员表按工作簿整体更新。新表头也会检查表外保留节点是否兼容。导入前保存源资产副本至 `Doc/Records/Stage04/ImportBackups`；写入失败尝试恢复已修改对象并删除本次新建节点，备份保留。

提交前同时检查工作区配置、节点集合、对象内容、资产文件以及工作簿SHA256。只保存本次涉及的资产，不调用全工程SaveAssets来顺带保存其他用户修改。

在已有资产上导回时，Bean回调默认字段、paramSign、enumValue、节点rowId/标题、通用表自定义结构名和Luban名等没有对应原表格列的元数据保留自原资产。工作簿本身不是这些元数据的完整备份；新建接收资产使用其默认值。

## 修正与边界

原节点写出曾把文件名ID放A列，而读取取B列；新实现统一以配置的ID数据列为准，A列只保留控制标记。原读取只读首行列表和非列表Bean首成员，本批完整读取续行和全部成员。

未知类型、重复ID/KEY、孤立续行、续行覆盖标量、公式单元格、过长单元格均明确失败。完全空白的列表项与原布局中的空占位无法区分，因此拒绝静默丢失。语言格式固定5列，不截断扩展语言。嵌套Bean参数在原模型没有类型绑定，未猜测实现。

导出生成数据工作簿，不保留既有文件样式、宏、图片或其他工作表。读取支持普通数值、inline/shared strings；公式需先粘贴为值。实际原项目Luban编译器与其配置尚未运行，不能宣称现有游戏配置即插即用。
